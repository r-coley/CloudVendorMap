Customer DC JSON Format
=======================

The uploaded JSON file must contain an array of location objects. To describe
customer data centers, set the provider field to exactly "CUSTOMER".

Example:

[
  {
    "provider": "CUSTOMER",
    "regionId": "customer-example-1",
    "regionName": "London Primary",
    "location": "London",
    "country": "United Kingdom",
    "companyAccessStatus": "enabled",
    "coordinates": {
      "lat": 51.5072,
      "lon": -0.1276
    },
    "status": "live",
    "dataCenterAddress": "123 Example Street, London",
    "sourceUrl": "https://example.com/internal-record",
    "lastVerified": "2026-11-26"
  },
  {
    "provider": "CUSTOMER",
    "regionId": "customer-example-2",
    "regionName": "Newport DR",
    "location": "Newport",
    "country": "United Kingdom",
    "coordinates": {
      "lat": 51.5842,
      "lon": -2.9977
    },
    "status": "live"
  }
]

Required fields
---------------

provider
  Must be "CUSTOMER" for customer data centers.

regionId
  A stable, unique identifier chosen by your organization.

coordinates.lat
  The latitude as a number.

coordinates.lon
  The longitude as a number.

Optional fields
---------------

You can also provide regionName, location, country, status,
dataCenterAddress, sourceUrl, lastVerified, and companyAccessStatus.

Approved locations
------------------

To mark a customer region as approved for your company, set:

  "companyAccessStatus": "enabled"

The "Approved locations" map-layer filter matches that exact value. Locations
without the field, or with any other value, are hidden when the filter is on.
The same field can be added to an item in an availabilityZones array when an
individual availability zone is approved.
Records with provider "CUSTOMER" are treated as approved automatically and do
not need companyAccessStatus.

After uploading the file, enable the "Customer DC's" filter to display the
customer locations on the map.

Cloud-region approval overlays
------------------------------

The customer file may also contain minimal approval records for cloud regions.
These records are merged at load time with the matching full record from the
generated cloud dataset:

{
  "provider": "OCI",
  "regionId": "uk-london-1",
  "companyAccessStatus": "enabled"
}

The provider and regionId must match an existing cloud record. Use
companyAccessStatus "enabled" to include it in the Approved locations filter;
omit the field or use another value to leave it unapproved. Approval overlays
do not need coordinates because the full cloud record supplies them.

To approve an individual availability zone, include the matching region ID and
an availabilityZones entry. The zone ID must match the full CSP record:

{
  "provider": "OCI",
  "regionId": "uk-london-1",
  "availabilityZones": [
    {
      "id": "uk-london-1-ad-1",
      "companyAccessStatus": "enabled"
    }
  ]
}

The Approved locations filter includes that AZ when its
companyAccessStatus is exactly "enabled". Coordinates are not needed in the
overlay because they come from the full CSP record.
